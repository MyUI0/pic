# Surge 脚本包 → Loon 版

## 范围与状态

全部 7 个 sgmodule 已转换为同名 lpx；9 个原脚本全部包含，并新增 TB_XY_Cookie.js 用于主插件淘宝/闲鱼分流。采用 Loon 官方文档中的传统 Script 语法。格式转换和离线测试完成，不代表真实签到可用；没有登录任何账号或请求签到接口。

## 发布与安装

沿用此前提供的 MyUI0/pic 仓库作为预设发布位置，尚未上传：

1. 将本目录全部文件上传到仓库的 `scripts/surge-loon/` 目录。不得只上传 lpx 而继续引用原作者脚本，否则本次修正不会生效。
2. 主插件预期地址：
   `https://raw.githubusercontent.com/MyUI0/pic/refs/heads/main/scripts/surge-loon/JD_Taobao_Xianyu.lpx`
3. 上传后在 Loon 添加该地址，启用插件、脚本及相应域名的 HTTPS 解密，并安装信任 Loon 证书。
4. 分别打开京东、京东金融对应活动，以及淘宝淘金币、闲鱼相关页面。收到保存通知仅说明捕获了 Cookie，不等于已验证登录有效。
5. 手动测试任务后再使用定时。应用可能不走可解密的 H5 请求，抓不到时需实际排查，不保证每个 APP 都能抓到。

这是预设路径，不是已发布的下载地址。如改仓库/目录，需同步替换所有 lpx 中的 script-path。

仅安装主插件即可。test.lpx、test2.lpx 到 test6.lpx 是原包调试模块的格式转换存档，不要和主插件同时启用，否则会重复执行。测试模块保留原来的部分窄匹配规则，不能作为功能完整版本。

## 本次修正

- Surge 的 `type=...` 改为 Loon http-request / cron 配置，去掉 `%APPEND%`。
- 抓取只读取 Header，无需读取请求体。
- 主插件淘宝/闲鱼使用一个分流入口：URL 含 idlefish 或 idle.fish 保存为 XY_COOKIE，mtop.taobao.coin 保存为 TB_COOKIE，其余不保存；其他域名、不同 API 命名需真机证据再适配。
- 完整保存 Cookie，避免原脚本过滤掉 _m_h5_tk 等字段；按 Cookie 名边界判断登录字段。
- Header 大小写不敏感；未变化的 Cookie 不重复通知；凭据不显示在通知中。
- 去掉京东脚本直接输出 Cookie 的日志；任务增加 Promise 异常兜底。
- 请求脚本用 $done({}) 放行原请求；任务超时统一 60 秒。
- test3/test4 补充解密域名。

## 原有问题与未验证部分

- TB_Coin.js 的签到参数仍是 sign=ff，其余淘宝请求缺少签名生成；XY_Checkin.js 同样没有签名生成。完整 Cookie 不会自动修复这些业务协议问题。
- 京东/京东金融接口地址、活动是否仍存在、签名要求及响应格式均未真实验证。
- 原脚本某些成功判定只判断外层返回状态，不能据此认定奖励到账；部分后续步骤失败没有纳入总状态。这些业务逻辑未在格式转换中重写。
- 本版不是已验证的全功能签到方案。若要求业务可用，需在本机抓取脱敏请求/响应逐个修复；不要公开 Cookie、Token 或完整抓包。
- 持久化只支持每个平台一份 Cookie，切换账号会替换对应平台的凭据。捕获完成后可关闭抓取规则，减少暴露面。
